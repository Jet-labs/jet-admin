Key flows

The four paths that exercise the whole diagram.

flow 1 · realtime ingest

Webhook → listener → action

  1. Source hits listener-proxy :8095/webhooks/… (or backend inline in dev)
  2. Engine routes raw event → Redis Stream listener:events
  3. Backend pipeline worker consumes, transforms, dispatches: trigger_workflow · trigger_query · save_to_buffer · push_to_app_page
  4. Browser updates via Socket.IO rooms
flow 2 · app request

Browser → backend → DB

  1. frontend :80 → backend :8090 REST (Firebase / API-key auth, Casbin)
  2. Module service → Prisma → postgres
  3. Listener CRUD also publishes listener:control → proxy hot-reloads
flow 3 · durable work

Workflow execution

  1. Trigger (API, listener action, cron) starts run via Temporal client
  2. temporal :7233 orchestrates; temporal-worker runs activities (DB/file access)
  3. Progress streams back over Socket.IO; Temporal UI :8088 for ops
flow 4 · AI agent

Jet Agent tool call

  1. Backend agent (OpenRouter) decides a tool is needed
  2. Calls mcp-server :5001/tenants/<id>/mcp with the user token
  3. Tool executes against the backend under the caller's own permissions
