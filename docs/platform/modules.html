Modules & Package Map

This page maps the repository by ownership. Use it when deciding where a change belongs, which API surface to call, and which package must be rebuilt.

Backend module pattern​

Every feature in apps/backend/modules/<name>/ follows the same shape:

FileResponsibility
<name>.v1.routes.jsExpress route table and middleware order
<name>.controller.jsRequest/response translation; calls one service method
<name>.service.jsBusiness logic, Prisma queries, transactions, policy grants
<name>.validator.jsZod request schemas
<name>.middleware.jsRequest enrichment for cross-resource authorization
<name>.errors.jsOptional domain errors (used by application)

Shared rules:

  • Routes mount under /api/v1/tenants/:tenantID/... unless explicitly global.
  • authMiddleware.authProvider runs once on the tenant router; individual routes call authorize(P.<resource>.<action>).
  • Cross-resource permissions use { ...P.x.y, reqKey: "xIDs", skipIfMissing: true }.
  • Services receive tenantID, userID, and authContext; they call grantCreatorAccess after create.
  • All responses use sendResponse; errors are normalized by the global handler in index.js.

Module notes​

tenant is a router aggregator. tenant.v1.routes.js mounts users, roles, API keys, cron jobs, datasources, listeners, queries, workflows, widgets, app pages, asset versions, bundles, folders, widget library, marketplace, templates, applications, and audit. Adding a tenant module means adding it there and to config/module.config.js dependencies if other modules depend on it.

application is the most coupled module. It compiles releases from app pages and their dependency graph. It reads asset versions, page configs, queries, workflows, and listeners; it does not execute live query IDs at runtime. Its compiler (application.compiler.js) is pure and separately testable.

assetVersion is shared infrastructure. It is mounted independently of the entity routers because it serves seven asset types with one permission model (<resource>:<assetID>). See Asset Versioning.

bundle owns import, not export routing. Export endpoints live on the owning entity routers (/queries/:id/export, /widgets/:id/export, …) and call bundleController.export*. POST /import/preview and /execute are the only routes under /import.

listener and listener-proxy are one logical system. The backend owns CRUD, validation, action dispatch, and Redis consumption. The proxy owns subscriptions and webhook HTTP ingress. Do not add subscription code to the backend; it would double-consume broadcast sources.

marketplace app templates are not just bundles. They can run schema and seed SQL, create roles/demo users, create cron jobs, and on uninstall drop prefixed tables with CASCADE. Treat template packages as trusted code.

Frontend data flow​

The API layer is deliberately thin: auth headers are attached centrally, base URL comes from /config.js or VITE_SERVER_HOST, and each module mirrors the backend route ownership. Business transformations belong in logic/, not in components.

Packages are npm workspaces and are built with npm run build:packages (scripts/build-packages.js). Several packages are dual ESM/CJS with dist/ outputs; backend requires the CJS build, frontend uses the ESM build. Rebuild a package after changing its source before testing the apps.

apps/mcp-server exposes the same registry over Streamable HTTP. Each request must carry a Firebase bearer token; the token is forwarded to backend REST calls, so tool execution uses the caller's Casbin permissions. The stdio entrypoint in packages/mcp-server uses one API key + tenant from environment variables and is intended for local MCP clients.

Dependency rules​

  1. packages/* must not import apps/*.
  2. apps/backend may import packages, never frontend code.
  3. apps/frontend may import packages, never backend code.
  4. Shared contracts belong in packages, not duplicated in both apps.
  5. dataQuery may depend on datasource; workflow may depend on dataQuery; appPage may depend on all three.
  6. assetVersion and bundle are cross-cutting and may read every asset table, but must not own feature-specific business rules.
  7. Listener subscriptions live only in apps/listener-proxy; backend listener code consumes events and dispatches actions.
