Platform Architecture

Jet Admin is a self-hostable internal-tools and analytics platform. The repository is an npm-workspaces monorepo (Node 20) containing a React SPA, an Express API, a standalone listener ingress service, an MCP bridge, shared TypeScript/JavaScript packages, and this Docusaurus site. The current platform version is 2.1.0-preview.1 (package.json).

Request and runtime flows​

1. Authenticated REST request​

Conventions that apply to every module:

  • Tenant routes are mounted under /api/v1/tenants/:tenantID/....
  • authMiddleware.authorize(P.<resource>.<action>) checks a Casbin permission in the tenant domain. Cross-resource checks pass extracted IDs via reqKey and skipIfMissing.
  • Responses use expressUtils.sendResponse, which spreads data into the top-level JSON object ({ success, ...data }).
  • Services filter by tenantID; creator access is granted after create.
  • Zod schemas validate requests; Prisma is the only database access layer.

2. Data query execution​

Queries are synchronous HTTP calls with a 60 s default execution timeout (overridable per query or workflow node). There is no platform-level row cap or read-only enforcement; those boundaries come from the datasource credential and connector. Long-running queries hold the request until the connector returns or the timeout aborts the connector call.

3. Workflow execution​

Temporal is the only workflow execution engine in the current code (apps/backend/modules/workflow/temporal/config.js explicitly says "native engine removed"). The backend starts an embedded Temporal worker during startup; a dedicated temporal-worker container can also consume the same task queue.

Defaults from temporal/policyDefaults.json: workflow run timeout 7 days, workflow task timeout 30 s, human-in-loop timeout 24 h, default node timeout 120 s, no retries after the first attempt unless configured. Per-node values override workflow defaults, which override platform defaults.

4. Listener event pipeline​

Only the listener-proxy subscribes to stateful sources. Every proxy serves all stateless webhook routes; stateful subscriptions are consistent-hash sharded across live proxies. A backend replica never subscribes, so a broadcast source is not double-consumed.

5. Application runtime (pinned release)​

The deployed client never receives a live query/workflow ID for execution. The release manifest resolves aliases to pinned versions; direct TRIGGER_QUERY / TRIGGER_WORKFLOW actions are removed at publish time. See Asset Versioning for the pinning and compilation contract.

Data model​

Domain tables use the tbl* prefix and UUID primary keys generated by gen_random_uuid() (Prisma schema.prisma); a few join/draft tables use composite or shared primary keys (tblUsersTenantsRelationship, tblApplicationDrafts). The core graph:

Key facts:

ConcernImplementation
Tenant assetstenantID column on datasources, queries, workflows, widgets, app pages, listeners, cron jobs, folders, applications, asset versions
Application compositiontblApplicationAssets has nullable typed targets plus composite FKs (tenantID, targetID) to prevent cross-tenant links
Immutable definitionstblAssetVersions stores a payload JSON snapshot, contentHash, monotonic per-asset versionNumber, and schemaVersion
Dependency edgestblAssetVersionReferences links parent asset versions to child versions and releases to pinned page versions
ReleasestblApplicationReleases.clientManifest / serverManifest; environments hold currentReleaseID; deployments are an append-only pointer history

Event buffertblListenerEvents with (listenerID, bufferName, seqNo) for durable listener observation
Global registriestblWidgetLibrary, tblMarketplaceItem, tblMarketplaceTemplate*, tblOperators are deployment-scoped, not tenant-scoped

Workflow nodes and edges cascade-delete with their workflow. Query and listener rows cascade from their datasource in several relations; tenant deletion is a service-level transaction that explicitly removes dependent rows. There is no PostgreSQL row-level security (RLS); tenant isolation is enforced in the application layer and, for application assets, by composite foreign keys.

Release object chain​

A release is thin: it stores the application definition plus exact page version IDs. Page and widget payloads are resolved from tblAssetVersions at runtime, not duplicated into the manifest. The stored clientManifest intentionally drops full pages and widgets maps after compilation.

Multi-tenancy​

Tenancy is a first-class boundary, not a UI filter.

  1. Identity — Firebase users (or tenant API keys) authenticate. Users have a global tblUsers row and a membership row per tenant.
  2. Tenant context — the tenant is taken from the URL (/api/v1/tenants/:tenantID) and validated against membership.
  3. Authorization — Casbin model sub, dom, obj, act evaluates role:.../user:... against a resource object (dataquery or dataquery:<id>) with an action such as list, in domain tenantID.
  4. Data access — services add tenantID to every where. Cross-tenant IDs are rejected by scoped lookups and, for application assets, by composite foreign keys.
  5. Global exceptions — operator sessions, the widget library, the marketplace, and app templates are deployment-global by design. Operator routes intentionally do not use Casbin; operator status is the grant.
  6. Secret isolation — datasource credentials are encrypted at rest and are never exported in bundles or returned in API responses.

There is no database-level RLS. A code path that forgets tenantID is a tenant isolation bug; review new Prisma queries accordingly. Operator endpoints and the MCP server are the only intentional cross-tenant surfaces.

The proxy registry uses Redis TTL heartbeats (10 s interval, 30 s TTL) and a consistent-hash ring. A backend sweeper reconciles placements every 30 s. If a proxy cannot fetch its shard, it subscribes to nothing (default-deny) rather than claiming all listeners.

Module gating and runtime configuration​

ENABLED_MODULES gates route imports in config/module.config.js. The code default in environment.js is only auth,tenant when the variable is absent; Compose enables the full set. isModuleEnabled also disables a module when any declared dependency is missing. A module that is disabled does not mount its router, so the API returns 404 for that area.

WORKFLOW_ENGINE_DRIVER is still read into environment.js but has no consumer in the workflow code path; do not use it to select a native engine. Temporal connection variables (TEMPORAL_ADDRESS, TEMPORAL_NAMESPACE, TEMPORAL_TASK_QUEUE, TLS settings) are the effective controls. See Configuration Reference and Deployment.

Architectural invariants​

  1. A tenant-scoped query always includes tenantID.
  2. Datasource credential material never appears in exports, logs, or asset configuration responses. Query result rows are caller-controlled data and are not value-scanned for secrets.
  3. Published application releases and asset versions are immutable.
  4. Runtime execution resolves pinned versions, not live asset IDs.
  5. The listener-proxy is the only subscriber; backend replicas compete on one Redis Stream.
  6. Temporal is the source of truth for workflow execution state; database rows are projections and logs.
  7. Folder scope is (tenantID, entityType), never cross-entity.
  8. Widget types are validated against @jet-admin/widget-types descriptors at authoring time.
