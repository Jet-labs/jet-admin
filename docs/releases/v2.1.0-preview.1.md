# v2.1.0-preview.1 — Marketplace and platform hardening

**Preview release — not a production-readiness or full-QA certification.**

This release collects the pending platform work since v2.0: a multi-type
marketplace, a first curated operations catalog, additional connectors, workflow
durability and authorization changes, and app-page/widget runtime improvements.

## Multi-type marketplace

- Add a deployment-wide marketplace model, migration and tenant/operator APIs.
- Browse datasources, widgets, workflows and app templates with search, type and
  category filters, pagination and dependency-aware install previews.
- Install bundles with fresh resource IDs; preserve dependency references and
  page widget-instance keys.
- Add operator verification/removal controls and marketplace permissions.
- Prevent stale SPA HTML from continuing to load obsolete marketplace bundles.

## Curated catalog: 35 substantive entries

The current curated tranche contains **9 workspaces, 12 playbooks, 10 focused
widget/page bundles and 4 configured datasource/query packs**. Examples include:

- Order fulfillment with inventory joins and nested payment-aware risk scoring.
- Receivables aging and parallel settlement-ledger reconciliation.
- Fraud review, bounded batch scoring and approval/reject/expiry paths.
- Subscription health, MRR exposure and approval-gated dunning proposals.
- SLA scoring, breach concentration, severity routing and escalation proposals.
- Privileged-access recertification and fail-closed approval proposals.
- Supplier exception intake, event contract/replay tools and public API enrichment.

Bundles include their dependencies, supported page layouts, source bindings,
setup instructions, sample inputs and explicit limitations. Focused widgets
include a companion runtime page where needed. Chart heights survive the editor
adapter round-trip; axes/legends use a readable plot surface.

**Scope correction:** the earlier 436-entry generator produced generic starters;
those rows are not 436 working integrations. The new default seed publishes only
the 35 curated entries and does not automatically award verified badges. The
400–500 substantive-item objective is **not yet achieved**. Demo fixtures and
proposal-only workflows must not be represented as production integrations.

## Datasources and integration safety

- Add ClickHouse, DuckDB, Prometheus, InfluxDB, File System, SFTP, GitHub, GitLab,
  SMTP and LDAP connector implementations/configuration.
- Improve listener reconnect/subscription lifecycle handling and webhook methods.
- Add confined HTTP request/redirect handling, path/input validation and credential
  log redaction protections.
- Tighten query-result caching so write operations are not served as cached reads.

These additions have targeted regression coverage; this preview does not claim
that every connector/provider operation has been manually verified live.

## Workflow execution and tenant boundaries

- Use the Temporal-only workflow runtime; deploy a matching Temporal service and
  worker rather than relying on the removed legacy execution path.
- Add durable ordered event history, final context/output projections and stable
  execution identity for retry/recovery handling.
- Improve human-input wait identity, delivery leasing, submission concurrency,
  cancellation and terminal-state persistence.
- Strengthen tenant-scoped resource references, workflow/socket observation and
  widget workflow authorization.
- Add durable cron occurrence tracking and listener acceptance/retry safeguards.
- Expand graph/runtime regressions for branching, joins, loops, child invocation,
  error handling, progress durability and terminal notifications.

## App pages, widgets and tooling

- Improve query coordination, shared-state/event dispatch, socket room lifecycle,
  workflow observation and widget-instance isolation.
- Add widget descriptors, normalization/validation and richer authoring contracts.
- Improve forms, date/date-range inputs, table interactions, embedded-content
  safety, template errors, notifications and responsive layouts.
- Add a cross-platform launcher with named presets and application combinations.
- Expand MCP catalog/introspection, administration and lifecycle tooling, plus
  datasource folders and related discovery/authoring support.
- Include standalone listener-proxy/worker deployment support and optional
  S3-compatible storage infrastructure configuration.
- Include deterministic platform showcase scenarios and repository-local QA
  planning/execution instructions. Private captures and backups are not shipped.

## Verification and known limitations

- The curated marketplace regression run passed **136 tests across 9 suites**:
  real embedded SQL, real DSL/node handlers with simulated transport, mocked
  imports/ID remapping, alias/graph guards, editor adapter layout round-trips,
  seed safety and scoped fixture-update protections.
- DeepSeek V4.1 Flash browser QA installed and exercised the renewal and support
  apps. The renewal filter changed the actual query inputs/results. A live
  support workflow completed and scored eight cases.
- Post-fix charts were inspected at desktop and 804px viewport width. Builder
  sidebar and table-column clipping remains at narrower widths; this is not a
  mobile usability certification.
- An explicit `externalWrites: 0` field was not visible in the persisted support
  run viewer/capture. That assertion remains partial; no external write was
  observed. Do not equate this with a proven zero-write invariant.
- Not all 35 entries have been manually installed, and public-provider execution
  and live approval resume/expiry coverage are incomplete.

## Upgrade notes

1. Back up the database. Review pending SQL migrations, especially workflow history
   locking/backfill changes, before deploying the matching backend and worker.
2. Use Node.js 20.x and the repository's existing dependency/build workflow.
3. From `apps/backend`, apply the pending migrations using
   `node scripts/run-manual-migrations.js`. This runner supplies the transactions
   required by the workflow migrations. Do not run the history-locking SQL outside
   a transaction. Regenerate Prisma Client with `npx prisma generate`.
4. Synchronize the permission registry with
   `node scripts/collect-and-seed-permissions.js`; review role grants for your
   deployment. Rebuild/restart the backend, worker and frontend as appropriate.
5. Preview catalog seeding with `node scripts/seed-marketplace.js` (no DB writes).
   Publish with `node scripts/seed-marketplace.js --apply`.
6. Existing deployments may explicitly add `--unverify-generated` to back up and
   remove unsupported verification claims only on the old built-in generator's
   rows. It does not delete entries or tenant-installed resources.

Local environment/credential changes, machine-local agent settings, DB backups,
build outputs and raw browser evidence are excluded from the commit. The tracked
MCP `.env` file is removed from version control; the local copy is preserved.
This does not scrub earlier Git history: rotate any real credentials that were
previously committed. Existing deployments still need their own secrets and
provider configuration.
