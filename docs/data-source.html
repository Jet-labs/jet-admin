Data Source

A data source is a saved connection: where the data lives, how to authenticate, and which connector implementation should execute queries or open listeners against it. Data sources are tenant-scoped and are the starting point for Data Queries and Listeners.

Core concepts​

ConceptMeaning
datasourceTypeCanonical connector key such as postgresql, restapi, or kafka. The value is validated against the connector registry; unknown types are rejected at create/update time.
datasourceOptionsConnector-specific JSON configuration (host, database, URL, authentication, TLS settings). Stored encrypted at rest.
Credential maskingCredential-like keys in API responses are replaced with ●●●●●●●●. Sending the mask back on update restores the stored secret.
Connection testA per-connector testConnection() call. It checks reachability/authentication, not the correctness of a future query.
ProxyA backend-mediated call to a small allowlist of connector helper methods, used by dedicated editors (Google Sheets, Excel/CSV, REST). Credentials never reach the browser.
Creator accessThe caller who creates a data source receives a wildcard Casbin policy on that data source.
File-backed sourceExcel/CSV data sources point at files uploaded to object storage with POST /upload.

Create a data source​

  1. Open Data sources in the tenant navigation.
  2. Choose Add data source.
  3. Enter a name (and optionally a description/tags).
  4. Select the connector type. The form below the selector is generated from GET /datasources/schemas for that type.
  5. Fill in connection details or a connection string.
  6. Choose Test to run testConnection() against the current form values.
  7. Choose Save.

The create request has this shape:

POST /api/v1/tenants/:tenantID/datasources HTTP/1.1
Authorization: api_key <raw-api-key>
Content-Type: application/json

{
  "datasourceTitle": "Orders (read replica)",
  "datasourceType": "postgresql",
  "datasourceOptions": {
    "connectionOption": "connectionDetails",
    "connectionDetails": {
      "connectionName": "orders-read-replica",
      "host": "db.internal.example.com",
      "port": 5432,
      "database": "orders",
      "user": "jet_reader",
      "password": "<db-password>",
      "sslMode": "require"
    }
  },
  "datasourceTags": ["production", "read-only"]
}

The response masks credential-like fields:

{
  "success": true,
  "datasource": {
    "datasourceID": "0e8f5f4a-3d1f-4f4b-9c3e-7a2d1c0b9a8e",
    "datasourceTitle": "Orders (read replica)",
    "datasourceType": "postgresql",
    "datasourceOptions": {
      "connectionOption": "connectionDetails",
      "connectionDetails": {
        "connectionName": "orders-read-replica",
        "host": "db.internal.example.com",
        "port": 5432,
        "database": "orders",
        "user": "jet_reader",
        "password": "●●●●●●●●",
        "sslMode": "require"
      }
    },
    "datasourceTags": ["production", "read-only"]
  }
}
warning

The update validator currently requires datasourceTitle, datasourceType, and datasourceOptions — a PATCH is effectively a full-form save. Read the data source first, then send back the complete object. Sending the masked sentinel keeps the existing secret; sending a new value replaces it.

Configuration reference​

Common fields​

FieldTypeRequiredNotes
datasourceTitleString, 1–255YesDisplay name. Not unique.
datasourceTypeRegistered keyYesValidated against the connector registry; cannot be an arbitrary string.
datasourceOptionsObjectYesConnector-specific. Stored as an AES-256-GCM envelope (__encrypted, iv, data, authTag).
datasourceDescriptionStringNoAccepted by the form/controller, but the current create/update service does not persist it. Use tags or the title for durable metadata.
datasourceTagsString arrayNoFree-form labels stored with the row.
folderIDUUIDNoOptional folder placement. See Folders.

PostgreSQL​

FieldNotes
connectionOptionconnectionDetails (default) or connectionString.
connectionDetails.connectionNameMinimum 3 characters.
connectionDetails.host / portPort defaults to 5432.
connectionDetails.database / user / passwordRequired when using details.
connectionDetails.sslModedisable, allow, prefer, require, verify-ca, verify-full. verify-* enables certificate verification.
connectionDetails.additionalOptions.connectTimeoutSeconds; converted to connectionTimeoutMillis.
connectionDetails.additionalOptions.applicationNameSent as application_name.
connectionStringFull postgresql://... URI.

REST API​

FieldNotes
baseUrlRequired. Query apiEndpoint values are appended to it.
timeoutSeconds; executor default is 15 when omitted.
authTypenone, basic, bearer, oauth2.
username / passwordUsed for Basic auth.
bearerTokenUsed for Bearer auth.
oauth2.clientId / clientSecret / tokenUrlAccepted by the connection tester. The current REST query executor does not acquire OAuth2 tokens; query execution applies only Basic/Bearer headers. Use a pre-issued Bearer token for queries until OAuth2 execution support lands.
headers / queryParamsArrays of { key, value }; query-level values override datasource defaults.
contentTypeapplication/json, application/xml, or text/plain.
followRedirects, sslVerifyPresent in the form schema and used by the connection tester, but not forwarded by the current query executor's Axios request. Treat them as connection-validation settings, not execution guarantees.

Other connectors​

The authoritative field list for any type is the JSON Schema returned by:

GET /api/v1/tenants/:tenantID/datasources/schemas?datasourceType=mongodb

The same schema drives the JSON Forms wizard, so UI labels and API field names stay aligned. Examples of type-specific structures:

{
  "mongodb": {
    "connectionOption": "connectionString",
    "connectionString": "mongodb+srv://<user>:<password>@cluster.example.com/orders"
  },
  "webhook": {
    "connectionName": "stripe-inbound",
    "allowedMethods": "POST",
    "authType": "header",
    "authHeaderName": "x-jet-signature",
    "authSecret": "<shared-secret>"
  },
  "excelcsv": {
    "fileInfo": {
      "fileUrl": "https://storage.example.com/excel-csv-datasources/<tenantID>/orders.xlsx",
      "fileName": "orders.xlsx",
      "fileType": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"
    }
  }
}
note

SQLite's databasePath and the File System connector's root path resolve on the backend host (or listener-proxy host for listeners), not on the user's machine. Use them only with paths you control and mount intentionally.

Test, health, and proxy behaviour​

ActionEndpointWhat it actually checks
Test unsaved formPOST /datasources/testConnector testConnection() with the supplied options.
Test saved sourcePOST /datasources/:datasourceID/test or GET /datasources/:datasourceID/healthDecrypts stored options and runs testConnection(). Both return healthy: true/false.
Validate a REST JSON endpointPOST /datasources/test-jsonrestapi only. Appends testPath to baseUrl, sends GET/HEAD, and checks that the response is parseable JSON rather than an HTML SPA shell.
Proxy a helper callPOST /datasources/:datasourceID/proxyLoads and decrypts the saved source, then calls an allowlisted connector method.
Upload Excel/CSVPOST /datasources/uploadMultipart file, 10 MB limit, .csv/.xlsx/.xls; returns a storage URL.

Proxy allowlist (anything else returns an error):

TypeAllowed actions
postgresql, mysql, mssql, sqlite, cockroachdb, oraclegetSchema, getSampleData, testConnection, runQuery, execute
mongodbgetSchema, getSampleData, testConnection, execute
googlesheetslistSpreadsheets, listSheets, previewData, readSheet, testConnection
excelcsvpreviewData, getColumns, testConnection
restapitestConnection, execute

Legacy alias keys (postgres, google_sheets, excel_csv, rest_api) are still present in the proxy allowlist for older saved rows, but new resources should use the canonical keys.

End-to-end example: PostgreSQL​

POST /api/v1/tenants/:tenantID/datasources HTTP/1.1
Authorization: Bearer <firebase-id-token>
Content-Type: application/json

{
  "datasourceTitle": "Analytics warehouse",
  "datasourceType": "postgresql",
  "datasourceOptions": {
    "connectionOption": "connectionString",
    "connectionString": "postgresql://analytics_reader:<password>@warehouse.example.com:5432/analytics?sslmode=require"
  }
}

Then verify the saved connection:

POST /api/v1/tenants/:tenantID/datasources/0e8f5f4a-3d1f-4f4b-9c3e-7a2d1c0b9a8e/test HTTP/1.1
Authorization: Bearer <firebase-id-token>
{
  "success": true,
  "datasourceID": "0e8f5f4a-3d1f-4f4b-9c3e-7a2d1c0b9a8e",
  "healthy": true,
  "connectionResult": { "ok": true }
}

Use it from a query with datasourceType: "postgresql" and a SQL statement. See the parameterized query example in Data Query.

End-to-end example: REST API source​

POST /api/v1/tenants/:tenantID/datasources HTTP/1.1
Authorization: api_key <raw-api-key>
Content-Type: application/json

{
  "datasourceTitle": "Fulfilment API",
  "datasourceType": "restapi",
  "datasourceOptions": {
    "baseUrl": "https://api.fulfilment.example.com",
    "timeout": 20,
    "authType": "bearer",
    "bearerToken": "<service-token>",
    "headers": [{ "key": "Accept", "value": "application/json" }],
    "queryParams": [{ "key": "region", "value": "eu" }],
    "contentType": "application/json"
  }
}

Validate that the endpoint is a JSON API (not a frontend shell):

POST /api/v1/tenants/:tenantID/datasources/test-json HTTP/1.1
Authorization: Bearer <firebase-id-token>
Content-Type: application/json

{
  "datasourceType": "restapi",
  "datasourceOptions": {
    "baseUrl": "https://api.fulfilment.example.com",
    "authType": "bearer",
    "bearerToken": "<service-token>"
  },
  "testPath": "/health",
  "testMethod": "GET"
}
{
  "success": true,
  "validationResult": {
    "ok": true,
    "validatedJson": true,
    "status": 200,
    "url": "https://api.fulfilment.example.com/health",
    "topLevelKeys": ["status", "version"]
  }
}

The saved source can now be selected in the query editor. A query sets apiEndpoint: "/v1/shipments", method: "GET", and maps {{inputs.*}} values into query params or the endpoint.

Credentials and encryption​

  • Data source options are encrypted with AES-256-GCM using VAULT_ENCRYPTION_KEY (64 hex characters = 32 bytes). Missing or wrong-length keys cause create/update/test/execute failures.
  • Vault-backed credentials (for example Google OAuth tokens and AI config) live in tblVaultCredentials, encrypted with the same key.
  • Responses mask keys matching credential patterns. Logs redact sensitive keys and credential-bearing URLs.
  • VAULT_ENCRYPTION_KEY has no automatic rotation. Rotating it without re-encrypting existing tblDatasources.datasourceOptions and tblVaultCredentials.encryptedData makes old rows undecryptable. Plan a migration and downtime.
danger

Use least-privilege database accounts. Jet Admin can execute arbitrary SQL through a SQL data source; read-only credentials are the only reliable guard against accidental writes from a saved query.

Use cases​

ScenarioRecommended pattern
Read-only reporting databaseDedicated read replica and read-only DB user. Use one data source per environment.
Internal REST servicerestapi source with a service token stored in bearerToken; one query per endpoint.
SaaS list/updateUse the dedicated connector (Stripe, Slack, Jira, GitHub) so query fields are typed instead of raw REST bodies.
Spreadsheet uploadsexcelcsv source plus POST /upload; replace the file URL when the sheet changes.
Event ingestionUse a listener-capable source (Kafka, MQTT, webhook, Redis, etc.), not a polling query. See Listeners.

Limitations and failure modes​

FailureCause / handling
Unsupported datasource typeThe datasourceType is not in DATASOURCE_LOGIC_COMPONENTS; use one of the keys listed above.
Connection test succeeds, queries failThe test may only prove reachability. Check credentials/permissions, query syntax, connector-specific execution limits, and the query's timeout. For REST OAuth2, the tester supports token acquisition but the executor does not.
Unable to decrypt datasource optionsVAULT_ENCRYPTION_KEY changed or does not match the key used when the row was written. Restore the key or re-encrypt the row.
Update silently keeps old credentialsThe request sent the ●●●●●●●● sentinel; that means "unchanged". Send a real new value to rotate.
Delete returns 409 DATASOURCE_IN_USEQueries owned by this source are referenced by app pages, widgets, workflows, or listener actions. Remove those references first.
Delete unexpectedly removes queries/listenersDatasource deletion cascades to its queries and listeners after the reference check passes. Export first if needed.
Proxy action rejectedThe action is not allowlisted for that type, or the method does not exist on the implementation.
File upload rejectedExtension must be .csv, .xlsx, or .xls; size must be ≤ 10 MB.
SQL data source sees the wrong databaseSQLite/filesystem paths resolve on the backend host; a container may have a different filesystem than your workstation.

Troubleshooting checklist​

  1. Test the saved source, not only the unsaved form. A saved row may still contain a rotated/masked secret.
  2. Check the exact type key with GET /schemas; aliases such as postgres are legacy, not canonical.
  3. Check tenant scope: the datasourceID must belong to the tenantID in the URL.
  4. Check references before deleting: 409 DATASOURCE_IN_USE includes the blocking queries in details.queries.
  5. Check object storage for Excel/CSV, logo, and widget uploads if URLs are broken.
  6. Check the listener proxy, not the backend, for listener connectivity; data source options used by listeners are decrypted in the proxy process.
