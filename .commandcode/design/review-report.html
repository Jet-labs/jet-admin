Design Review: Jet Admin

Product — App UI / Admin Internal-Tool Builder
Surface: Sign-in, sign-up, protected layout, app page builder
2026-06-20

First Impression

The dark indigo theme signals "developer tool" immediately — and correctly. The three-panel builder (editor sidebar | canvas | console) looks like the right tool for the job. Resizable panels and a custom drag-and-drop layout engine say the team has invested in the hard problems.

But the product's visual personality stops at "competent dark theme." The sign-in page is interchangeable with any SaaS product. The nav bar has a 2px purple bottom border that draws the eye but carries no meaning. The builder works well but doesn't leave a memorable impression.

Hierarchy — Walkthrough

Entry (Sign-in)

Centered card layout — logo row at top, form below. Section card component provides a visual container. Label placement above inputs follows convention well. Clear focus hierarchy: logo → form → submit → Google button → sign-up link.

Protected Layout

Three-tier nesting is sound architecture. Top nav has logo (left), breadcrumbs (center), user avatar (right). Sidebar uses resizable panels with Radix accordion. Active state highlighting uses bg-primary/5 — visible but subtle.

Builder Surface

Three-zone layout (editor 20% | canvas 80% | console 25%) creates clear operational hierarchy. Canvas is the dominant surface. Floating LayoutNodeToolbar on selection is a good space-saver.

Typographic hierarchy is flat. All headings use font-weight: 400. Only line-height distinguishes h1 from h2 from h3. Sidebar nav items use font-semibold, creating a mismatch where nav labels feel heavier than page headings.

Color Voice

The palette commits to one hue: #7582ff (indigo-purple) — primary, accent, link, focus, success, and active indicator simultaneously. The brand's entire semantics run on a single hue plus gray neutrals.

What works: The dark theme is cohesive. --brand-dark (#171717) and --brand-dark-card (#1F1F1F) create subtle surface distinction. Border steps show depth thinking.

Success = Primary. The MUI theme maps success.main to #7582ff — the same purple as primary. There is no green. "Success" and "primary action" are visually identical.
Naming confusion. .link-lime styles links in blue (#3e71cf). .link-purple styles links in white (#fafafa). Names describe neither the color nor the function.
Google SSO button hardcodes bg-[#4285F4] inline — breaks the design system. No warning color exists (only destructive red). Darkest surfaces are pure neutral — a whisper of indigo chroma would feel authored.

Type Voice

The font stack targets "Circular" — a paid Lineto typeface. If licensed, distinctive. If not, the fallback (Helvetica Neue, Arial) is generic system text.

No type system. No defined scale. No clamp(), no fluid type, no leading trim. All headings at font-weight: 400 — on a dark background, light headings recede instead of commanding attention.
h1 line-height: 1.00 — descenders on letters like "g" and "j" will collide with the line above. Most h1 elements in the app are page titles that should breathe.

Only one defined label style (.label-caps at 12px uppercase monospace). No secondary, tertiary, or caption size. On dark backgrounds, font-weight: 400 body text at 16px is readable but not comfortable for longer content.

Interaction Feel

Strengths:

  • Drag-and-drop has thorough visual feedback: glow indicators, hover resize handles, row border highlights, dashed empty zones
  • Undo system with "N unsaved changes" badge is a UX win
  • Floating toolbar appears contextually on selection
  • ReactQueryLoadingErrorWrapper provides consistent loading/error/empty states
  • Toast system is visually consistent with dark theme
outline: none !important on buttons removes the native focus indicator. The custom box-shadow fallback works on supported elements but !important blocks any override.
Sign-in error copy is generic: "Sign in error! Please check your credentials and try again!" tells the user nothing actionable. The sign-up form serializes the raw error object (JSON.stringify(error)) — technical noise for end users.

Top Recommendations

1. Redesign color semantics

Mode: recolor

Add a green for success states (distinct from primary). Add amber for warnings. Keep purple as primary only. This fixes the most confusing visual bug in the system.

2. Build a type system

Mode: typeset

Define a 5-step type scale (h1, h2, h3, body, caption) with distinct weights: h1/h2 at 600-700, body 400, caption 500. Add clamp() for fluid sizing.

3. Fix heading weight on dark

Mode: refine

Increase h1/h2 to font-weight: 600-700. Relax h1 line-height from 1.00 to 1.15 minimum. Headings on dark need weight to command attention.

4. Add interaction state audit

Mode: interaction

Audit disabled states (gray-on-gray is common). Remove outline: none !important. Restore visible focus rings.

5. Add brand atmosphere to auth pages

Mode: refine / surface

The sign-in/up cards sit on a flat dark background with no texture or depth. A subtle gradient or atmospheric element would make the entry feel authored.

6. Rename .link-lime and .link-purple

Mode: refine

Name them by function: link-brand, link-muted. Current names describe neither color nor function.

7. Improve error messages

Mode: writing

Replace "Sign in error! Please check your credentials" with the actual reason. Replace JSON.stringify(error) on sign-up with formatted message.
